# RezoneVPN — прототип 0.6.4

## Автообновления

Windows-приложение собирается как пользовательский NSIS-установщик. Установленная сборка проверяет HTTPS-feed `https://64-188-64-28.sslip.io/updates/`; при наличии новой версии пользователь нажимает «Обновить», затем «Перезапустить и установить». Этот рабочий адрес временный: `rezonevpn.play2go.cloud` пока не разрешается в IP, поэтому после настройки DNS потребуется заменить feed URL и выпустить переходную версию.

Настроен generic feed `https://64-188-64-28.sslip.io/updates/`. На сервере должны быть доступны с теми же именами файлы, созданные сборкой: `latest.yml`, установщик `.exe` и соответствующий `.blockmap`.

Для каждого выпуска обновите версию в `package.json`, `package-lock.json`, `renderer.js`, боковой панели и журнале, затем выполните `npm ci` и `npm run dist:win`. GitHub Actions можно запустить вручную через **Actions → Build Windows update package → Run workflow**; сборка создаёт артефакт с `.exe`, `.blockmap` и `latest.yml`.

На VPS должен быть установлен Caddy. Каталог `/srv/rezonevpn-updates/` должен быть доступен на запись пользователю публикации и на чтение Caddy. Замените `rezone-deploy` на имя созданного SSH-пользователя:

```bash
sudo install -d -o caddy -g caddy -m 2775 /srv/rezonevpn-updates
sudo usermod -aG caddy rezone-deploy
```

Переподключитесь по SSH, чтобы применилось членство в группе. Добавьте блок из `deploy/Caddyfile` в текущую конфигурацию Caddy (не заменяйте существующий файл целиком), затем проверьте и примените её:

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

Для автоматического HTTPS домен должен иметь публичную A-запись на IP VPS, а входящие TCP-порты 80 и 443 должны быть доступны. После настройки SSH-ключа (пароль не передавайте в чат) публикуйте собранные файлы из каталога проекта:

```bash
./deploy/publish-updates.sh rezone-deploy@your-vps
```

Скрипт сначала загружает установщик и `.blockmap`, а `latest.yml` публикует последним, чтобы клиенты не увидели метаданные раньше файлов. Имена файлов сборки не меняйте.

Сборки 0.6.2 и 0.6.3 ищут обновления на GitHub, а не на VPS. Чтобы перейти на VPS-feed, им нужно один раз вручную установить NSIS-сборку 0.6.4. После этого следующие версии смогут приходить с VPS. Portable-версия не поддерживает штатную установку обновлений.

## Ограничения прототипа

- VPN-туннель не реализован: выбор локаций, режима и сервисов не маршрутизирует трафик; системный прокси не настраивается. Для реального VPN нужны протокол/клиент, серверные конфигурации и системная интеграция.
- Каталог товаров локальный и не синхронизируется с сайтом.
- Авторизация и аккаунты хранятся локально и не являются production-системой. Не используйте настоящие пароли или чувствительные данные.

## Проверка внешнего IP

Карточка «Проверка сети» получает внешний IP и приблизительную страну/регион/город через HTTPS API `ipapi.is`, без ключа. Результаты геолокации приблизительны, а IP передаётся стороннему сервису. См. [документацию API](https://ipapi.is/developers.html). Переключатель «Скрыть IP» хранится локально.

## Сборка Windows x64

```bash
npm ci
npm start
npm run dist:win
```

Обычная сборка создаёт установщик в `dist/`, не публикуя его. Workflow запускается по тегу `v*` или вручную и сохраняет сборку как GitHub Actions artifact. После распаковки артефакта поместите `.exe`, `.blockmap` и `latest.yml` в `dist/`; затем опубликуйте их скриптом `deploy/publish-updates.sh`.
